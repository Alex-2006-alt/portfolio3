# 📁 Portfolio — Project README

A full-stack personal portfolio website built with **Next.js 16**, **Prisma ORM**, **NextAuth**, and **shadcn/ui**.  
It has a public-facing portfolio and a protected admin dashboard to manage all content.

## 🗄️ Database Models

All data lives in a single SQLite database (`dev.db`) managed by Prisma.

| Model        | What it stores                                         | Admin page         |
|--------------|--------------------------------------------------------|--------------------|
| `User`       | Admin login accounts (email + hashed password)         | `/admin/admins`    |
| `Project`    | Portfolio projects (title, description, image, link)   | `/admin/projects`  |
| `Experience` | Work experience entries (role, company, date, desc)    | `/admin/experience`|
| `Skill`      | Skill cards (title, description, stat value/label)     | `/admin/skills`    |
| `TechStack`  | Tech stack badges (name, category, icon name)          | `/admin/tech-stack`|
| `Settings`   | Global settings (your name, bio, email, social URLs)   | `/admin/settings`  |

> All models have an `order` field so you can reorder entries.

---

## 🔐 Authentication

- **Library**: NextAuth v4 with Credentials provider
- **Strategy**: JWT sessions (no database sessions)
- **Login page**: `/admin/login`
- **Protected routes**: Anything under `/admin/*` and `/api/admin/*` is blocked by `middleware.ts`
- **Password storage**: bcrypt-hashed in the `User` table

## ⚙️ Environment Variables

Defined in `.env` at the project root. **Never commit this file to Git.**

| Variable                            | What it does                                      | Example value           |
|-------------------------------------|---------------------------------------------------|-------------------------|
| `DATABASE_URL`                      | Path to the SQLite DB file                        | `file:./dev.db`         |
| `NEXTAUTH_URL`                      | Full URL of your site (must match deployment URL) | `http://localhost:3000` |
| `NEXTAUTH_SECRET`                   | Secret used to sign JWT tokens                    | Any long random string  |
| `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` | Your Cloudinary account cloud name                | `your_cloud_name_here`  |
| `CLOUDINARY_API_KEY`                | Cloudinary API key                                | `123456789012345`       |
| `CLOUDINARY_API_SECRET`             | Cloudinary API secret                             | `your_api_secret_here`  |

> For production on Vercel, all these must be added in **Vercel Dashboard → Project → Settings → Environment Variables**.

## 🚀 Running Locally

```bash
# 1. Install dependencies
npm install

# 2. Set up the database (creates dev.db and runs migrations)
npx prisma db push

# 3. Seed the first admin user
ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD=StrongPassword123! node seed_admin.mjs

# 4. Start the development server
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) to see the public portfolio.  
Open [http://localhost:3000/admin/login](http://localhost:3000/admin/login) to access the admin panel.

**First-time admin login**:
Use the email and password you provided via `ADMIN_EMAIL` and `ADMIN_PASSWORD` to the `seed_admin.mjs` script.

## ⚠️ Production Notes

- The local `dev.db` SQLite file **cannot be used on Vercel** (serverless has no persistent disk).
- For deployment you need a cloud database: **Turso** (SQLite-compatible) or **Neon** (PostgreSQL).
- Update `NEXTAUTH_URL` to your production domain before deploying.
- Change the default admin password after first deploy.
